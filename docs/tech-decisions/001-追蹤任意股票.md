## 1. 需求回顧

### 核心問題

#### 問題 1：加入追蹤需「搜尋 → 跳頁 → 點愛心」三步

**現況分析**：

```
SearchBar.vue（導覽列）
  └─ 結果列僅含 代號 + 名稱
       └─ 點名稱 → onSelect → 導航至 /stock/:code（詳情頁）
            └─ 詳情頁才有 WatchlistButton（phase-5a 既有）
```

- 使用者若想在搜尋階段就直接追蹤，必須先跳詳情頁再回頭，流程中斷
- 追蹤清單頁（/watchlist）目前**沒有**搜尋欄，空狀態時只能靠首頁搜尋補追蹤

#### 問題 2：追蹤清單只顯示有「未來配息」的股票（009 已處理，本功能沿用）

**歷史根因**：

```
WatchlistView.vue（009 之前）
  └─ watchlistUpcoming = upcoming.value.filter(item => watchedCodes.has(item.code))
       └─ 無配息紀錄（ex_date 已過或從未配息）的追蹤股票會從視圖「消失」
```

**現況（009 已實作，程式碼已驗證）**：

```
components/WatchlistView.vue ✅
  └─ allWatchedItems = items.map(item => ({ ...item, dividend, hasUpcomingDividend }))
       └─ 張數以 useWatchlist.items 為準，upcoming 只作為配息補充
            └─ 無配息 → WatchlistItemRow 顯示「無近期配息」
```

→ 本功能不需重做此區塊，剩餘差距是「追蹤清單頁沒有搜尋欄」與「加入的股票 type 不確定」。

#### 問題 3：type 判定資料源不足（已實測）

| 資料源 | 欄位 | 可否判定 stock/etf/preferred |
|--------|------|------------------------------|
| `api/securities-index.json`（1377 筆） | 僅 `{code, name}` | ❌ 無 type 欄位 |
| `api/upcoming.json`（106 筆） | `type` = 「息」(77) /「權息」(16) /「權」(13) | ❌ 是**配息形式**（現金/股票/兩者），非證券類型 |

→ 兩個資料源都無法直接派生 `WatchlistItem.type`，需保守處理。

### 用戶期望（23 條驗收重點）

| 期望 | 現狀 | 差距 |
|------|------|------|
| 搜尋結果直接追蹤（不需跳頁） | 結果列無 ❤️ | 每列加 ❤️，點 ❤️ 不關下拉、不導航 |
| 追蹤清單頁可直接搜尋加入 | /watchlist 無搜尋欄 | 頁面頂部加搜尋欄（空狀態也可用） |
| 追蹤無配息/下市股票仍顯示 | 009 已支援（「無近期配息」） | 沿用；確認新增路徑也符合 |
| 隱私模式可用 | init/write 已 try/catch | 補測試驗證 + 不干擾使用者 |
| 手機可點 ❤️、可用追蹤清單頁搜尋欄 | 頭部收合邏輯存在、觸控目標 40px | 觸控目標提高、頁面常駐搜尋欄 |

### 範圍界定

| 項目 | 內容 |
|------|------|
| **包含** | 搜尋結果列 ❤️（slot 架構 + 防誤導航）、追蹤清單頁搜尋欄、無配息顯示沿用與驗證、localStorage 降級測試、手機觸控目標 |
| **不包含** | 後端/爬蟲/processor 變更（type 判定與 securities-index 擴充僅列為衍生工作）、搜尋演算法改進、多裝置同步、追蹤上限 |
| **相依** | phase-5a（useWatchlist / WatchlistButton / 徽章 / 詳情頁）、009（WatchlistView allWatchedItems 架構） |

## 2. 候選方案

### 決策 1：搜尋結果 ❤️ 的 UI 架構

| 方案 | 描述 | 關鍵差異 |
|------|------|---------|
| **🟢 A. 具名 Slot 擴充** | SearchBar 新增 `<template #result-actions="{ result }">`，父層注入 WatchlistButton | SearchBar 保持與 watchlist 領域完全解耦；兩使用點（navbar、追蹤清單頁）共用同一 slot |
| 🟡 B. Prop 標記擴充 | SearchBar 加 `:show-watch-toggle="true"`，內部直接渲染 WatchlistButton | SearchBar 反向依賴 watchlist 領域（import useWatchlist），但使用點最簡 |
| 🔵 C. 新元件 SearchResultRow | 把結果列抽成獨立元件，❤️ 作為可選區塊 | 結構最乾淨，但僅 2 個使用點，且需重複維護 blur/mousedown 行為 |

### 決策 2：追蹤清單顯示無配息股票（含追蹤清單頁搜尋欄）

| 方案 | 描述 | 關鍵差異 |
|------|------|---------|
| **🟢 A. 沿用 009 前端分離 + 補頁面搜尋欄** | 核心邏輯不動（items 為主、upcoming 為補）；`views/WatchlistView.vue` 頂部加常駐 SearchBar | 純前端、零 API 變更、與已實作架構一致 |
| 🟡 B. 反轉資料源（upcoming 為主） | 以 upcoming 過濾追蹤清單 | 回到 009 前的 bug（無配息股票消失），直接淘汰 |
| 🔵 C. 後端新增 watchlist API | processor 產出追蹤清單完整資料 | 追蹤清單在前端（localStorage），後端對其不可見，過度設計 |

### 決策 3：type 判定

| 方案 | 描述 | 關鍵差異 |
|------|------|---------|
| **🟢 A. 保守預設 'stock'** | 沿用 `useWatchlist.add` 既有預設；所有新加入一律 'stock' | 零成本、不猜測；type 目前 UI 未顯示，無可見影響 |
| 🟡 B. 用 upcoming.type 對應 | 「息」→stock、「權息」→stock 等對應表 | **錯誤對應**：upcoming.type 是配息形式非證券類型；且僅 106 筆有資料，覆蓋率不足 |
| 🔵 C. Processor 擴充 index 加 type | 爬蟲資料源附帶市場別（上市/上櫃）推導 | 屬 009 問題 2 的衍伸，超出本功能「純前端、無 API 變更」邊界；列為衍生工作 |

### 決策 4：localStorage 失敗降級

| 方案 | 描述 | 關鍵差異 |
|------|------|---------|
| **🟢 A. 沿用既有 try/catch + 補測試** | init（讀）與 watchEffect（寫）已有 try/catch；補齊「setItem/getItem 拋錯」的單元測試 | 不改 runtime 行為，用測試鎖住降級保證 |
| 🟡 B. Storage Adapter 抽象 | 包一層可注入的 storage 介面 | 過度設計：目前只有一個 storage key、一個 consumer |
| 🔵 C. 失敗時 UI 提示 | 偵測不可寫入後顯示警告 | 違反 IF「屬於預期行為（隱私模式）」的定位，多餘打擾 |

### 決策 5：手機版互動

| 方案 | 描述 | 關鍵差異 |
|------|------|---------|
| **🟢 A. sm 尺寸 + mobile 放大 + 頁面常駐搜尋欄** | 搜尋結果 ❤️ 用 `size="sm"`（40px），`@media (max-width: 767px)` 提高到 44×44px；追蹤清單頁搜尋欄不放 header、頁面頂部常駐 | 觸控目標達標；追蹤清單頁搜尋欄不受 header 的 `width: 0` 收合規則影響 |
| 🟡 B. 沿用現有 40px 不做調整 | 不變更尺寸 | 40px 略低於 iOS 44pt 建議值，觸控誤差提升 |
| 🔵 C. 追蹤清單頁搜尋欄也做收合圖示 | 比照 header 的 toggleExpand 行為 | 頁面內多一個折疊步驟，與 IF「空狀態時搜尋欄也可用」不符 |

### 決策 6：與 phase-5a 兼容（防誤導航機制）

| 方案 | 描述 | 關鍵差異 |
|------|------|---------|
| **🟢 A. WatchlistButton 內建 `@mousedown.stop`（行為相容強化）** | 在 WatchlistButton 根元素加 `@mousedown.stop`，配合既有 `@click.stop`；列仍以 `@mousedown.prevent` 觸發導航 | 一次改動保護所有使用點（詳情頁/列表/搜尋列）；既有呼叫無感 |
| 🟡 B. 僅在搜尋列 slot 包裹層加 `@mousedown.stop` | 不更動 WatchlistButton | 需在每個使用 SearchBar 的 slot 重複，且 WatchlistItemRow / 詳情頁的 ❤️ 仍無此保護 |
| 🔵 C. 將列導航改為 `@click` | 捨棄 mousedown.prevent 機制 | 改變既有 blur+setTimeout 競態平衡，波及首頁既有流程，風險高 |

### 為什麼放棄其他方案

- **決策 1 Prop 標記（B）**：SearchBar import `useWatchlist`/`WatchlistButton` 會把通用搜尋元件綁死追蹤領域；本功能有兩處使用點，未來若出現第三種 action（如「快速加入行事曆」）需再改元件。
- **決策 1 SearchResultRow（C）**：僅 2 使用點，新元件要重驗 blur/`@mousedown.prevent` 的競態行為，開發成本最高。
- **決策 2 反轉資料源（B）**：等同復現 009 修復前的缺陷（無配息股票消失），直接違反驗收 017–019。
- **決策 3 upcoming 對應（B）**：語意錯誤（息/權息/權 ≠ stock/etf/preferred），寧缺勿錯。
- **決策 4 Adapter / UI 提示（B/C）**：單一 storage key 不值得抽象層；提示違反 IF「隱私模式為預期行為、不干擾」。
- **決策 5 維持 40px（B）／收合圖示（C)**：40px 低於建議觸控目標；頁面內再折疊與 IF「空狀態時搜尋欄仍可用」衝突。
- **決策 6 slot 包裹（B）**：每個使用點重複 `@mousedown.stop`，且詳情頁/列表的 ❤️ 仍無保護；改 `@click`（C）風險最高，不採用。

## 5. 詳細設計

### 5.1 SearchBar.vue：新增具名 Slot

**改動前**（結果列渲染）：

```vue
<div
  v-for="result in results"
  :key="result.code"
  class="search-result-item"
  role="option"
  @mousedown.prevent="onSelect(result)"
>
  <span class="result-code">{{ result.code }}</span>
  <span class="result-name">{{ result.name }}</span>
</div>
```

**改動後**：

```vue
<div
  v-for="result in results"
  :key="result.code"
  class="search-result-item"
  role="option"
  @mousedown.prevent="onSelect(result)"
>
  <div class="result-main">
    <span class="result-code">{{ result.code }}</span>
    <span class="result-name">{{ result.name }}</span>
  </div>
  <!-- 父層注入 ❤️（SearchBar 不依賴 watchlist 領域） -->
  <slot name="result-actions" :result="result" />
</div>
```

- 既有「點名稱導航」行為不變：`@mousedown.prevent` 仍綁在列上，搶在 blur+setTimeout(150ms) 前完成導航。
- 未提供 slot 時維持現行外觀（`v-if`/預設內容可省略，直接 render 為空即原樣）。

### 5.2 WatchlistButton.vue：內建 `@mousedown.stop`

**改動後**：

```vue
<button
  class="watchlist-btn ..."
  :aria-label="..."
  aria-pressed="..."
  @click.stop="handleClick"
  @mousedown.stop   <!-- 新增：阻止 mousedown 冒泡到結果列的導航 handler -->
>
```

**防誤觸機制說明**：

```
使用者點擊搜尋結果的 ❤️
  ├─ mousedown → WatchlistButton @mousedown.stop
  │     └─ 不冒泡到列的 @mousedown.prevent → 不導航、input 不失焦 → 下拉保持顯示 ✅
  ├─ click → WatchlistButton @click.stop
  │     └─ 不冒泡到列的任何 click → 不導航 ✅
  └─ 結果：僅 toggle 追蹤；導覽列徽章 ±1（watchlist singleton 自動響應）
```

- Vue 3 fallthrough：非 emits 宣告的事件會落到元件根元素（`<button>` 單一根節點），`@mousedown.stop` 寫在 `<WatchlistButton>` 上同樣成立；但內建在元件內可一次保護詳情頁/列表/搜尋列所有使用點。

### 5.3 App.vue（導覽列）與 views/WatchlistView.vue（追蹤清單頁）

兩處父層注入同一套 slot 內容（追蹤清單頁為新新增）：

```vue
<SearchBar v-model="query" :results="results" @select="onStockSelect">
  <template #result-actions="{ result }">
    <WatchlistButton
      :code="result.code"
      :name="result.name"
      type="stock"        <!-- 決策 3：保守預設 -->
      size="sm"
    />
  </template>
</SearchBar>
```

- 導覽列（App.vue）與追蹤清單頁各自有獨立的 `useSearch` query/results 狀態，互不干擾；`securities-index.json` 會被載入兩次，瀏覽器快取可緩解（已知行為，非問題）。
- 追蹤清單頁搜尋欄放置位置：`views/WatchlistView.vue` 的標題下方、`<WatchlistView />` 元件上方；空狀態（`WatchlistEmpty`）時搜尋欄仍常駐可用（驗收 015）。

### 5.4 追蹤清單無配息顯示（決策 2）

**核心邏輯（009 已實作，本功能不動）**：

```
components/WatchlistView.vue
  ├─ allWatchedItems = items.map(item => ({ ...item,
  │     dividend: upcoming.find(u => u.code === item.code),      // 可能 undefined
  │     hasUpcomingDividend: !!dividend }))
  ├─ watchlistUpcoming（有配息者）→ 行事曆日期標記              → 行事曆模式不變
  ├─ sortedAllItems（全部追蹤項目）→ 列表模式 / 行事曆下方概覽    → 無配息顯示「無近期配息」
```

- 本功能的驗證重點是「新加入路徑（搜尋結果 ❤️）產生的無配息股票」與「下市股票」都能正確顯示（驗收 017–019），需補 E2E 情境。

### 5.5 type 判定（決策 3)

- `useWatchlist.add/toggle` 維持既有簽章與預設 `type: 'stock'`（程式碼已驗證）。
- 所有新增呼叫點（搜尋列 slot、追蹤清單頁 slot、既有詳情頁）統一以 `'stock'` 傳入，不做資料源猜測。
- **衍生工作（不納入本功能）**：processor 在產出 `securities-index.json` 時附帶市場別（上市/上櫃，009 爬蟲已有 `market` 欄位），ETF/特別股需額外清單；屆時再於 `useWatchlist` 加入 type 淨化（讀入時未知 type 預設 'stock'）。

### 5.6 localStorage 降級（決策 4）

- 既有行為（已驗證）：`init()` 讀取 try/catch；`watchEffect` 寫入 try/catch → 隱私模式下 in-memory singleton 正常運作，僅不持久。
- 本功能增加：單元測試鎖定「`localStorage.setItem` / `getItem` 拋錯」時 toggle 仍正常、UI（items）即時更新、不 crash。
- 可選優化（非必要）：首次寫入失敗後設 flag 停止後續 watchEffect 嘗試，避免每次變動重複例外開銷；以「追蹤上限不超過 100 支、寫入為小 payload」而言，現況效能無虞。

### 5.7 手機版（決策 5）

- 搜尋結果列高已為 44px（`style.css`），❤️ 使用 `size="sm"`（現 40px）。
- 新增 mobile 覆寫（`style.css`）：

```css
@media (max-width: 767px) {
  .search-result-item .watchlist-btn--sm {
    width: 44px;
    height: 44px;
  }
}
```

- 追蹤清單頁搜尋欄放在頁面內容區（非 header），不受 `.header-icon-group .search-bar { width: 0 }` 收合規則影響（該規則僅作用於 header 內）；mobile 直接顯示、可輸入、可點結果 ❤️。

### 5.8 phase-5a 兼容（決策 6）

| 既有功能 | 本功能改動 | 是否破壞 |
|---------|-----------|---------|
| 詳情頁 ❤️（StockView `size="lg"`） | 無改動；WatchlistButton 多 `@mousedown.stop`（無感強化） | 否 |
| 列表 ❤️（WatchlistItemRow `size="sm"`） | 同上 | 否 |
| 追蹤清單頁行事曆/列表模式 | 僅在頁面層新增上方搜尋欄，元件內部不動 | 否 |
| 導覽列徽章（items.length） | 沿用 singleton，自動 ±1 | 否 |
| 首頁搜尋導航 | 列 `@mousedown.prevent` 不變 | 否 |
